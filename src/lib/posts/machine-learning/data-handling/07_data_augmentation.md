# 07. 데이터 증강

## 개요

데이터 증강은 학습 샘플을 변형하거나 원본 사이의 새로운 샘플을 만들어 모델이 더 다양한 입력을 보도록 하는 방법입니다. 데이터가 적을 때 과적합을 줄이는 데 도움을 줄 수 있지만, 행을 늘리기만 한다고 정보가 늘어나는 것은 아닙니다. 변환 뒤에도 정답이 유지되고, 만들어진 데이터가 실제로 나타날 법해야 효과를 기대할 수 있습니다.

예를 들어 고양이 사진을 조금 회전해도 고양이라는 정답은 유지될 수 있습니다. 반면 손글씨 숫자 6을 뒤집으면 9처럼 보일 수 있고, 의료 영상의 좌우를 바꾸면 병변 위치의 의미가 달라질 수 있습니다. 어떤 변형이 타당한지는 데이터와 문제의 의미로 결정합니다.

## 이미지 증강

이미지는 회전, 이동, 크롭, 밝기·대비 조절, 약한 노이즈 추가로 촬영 각도나 조명 차이를 흉내 낼 수 있습니다. 학습 중 매번 조금씩 다른 변형을 주면 모델이 특정 픽셀 배치만 외우는 것을 줄이고, 작은 입력 변화에도 같은 클래스를 예측하도록 학습할 수 있습니다.

```python
from torchvision import transforms

train_transform = transforms.Compose([
    transforms.RandomResizedCrop(size=224, scale=(0.8, 1.0)),
    transforms.RandomHorizontalFlip(p=0.5),
    transforms.ColorJitter(
        brightness=0.15,
        contrast=0.15,
    ),
    transforms.ToTensor(),
])
```

변형의 세기를 과하게 키우면 이미지의 의미가 달라집니다. 얼굴 인식에서 좌우 반전이 허용될 수 있지만, 문자 인식이나 좌우 방향이 중요한 의료 영상에서는 위험할 수 있습니다. 객체 탐지나 이미지 분할에서는 이미지에 기하 변환을 적용할 때 bounding box나 segmentation mask에도 같은 변환을 적용해야 입력과 라벨이 맞게 유지됩니다.

## 텍스트 증강

텍스트에서는 동의어 치환, 역번역, 문장 재구성, 사전학습 언어 모델을 이용한 문장 생성 등을 사용할 수 있습니다. EDA(Easy Data Augmentation)는 동의어 교체·랜덤 삽입·랜덤 교체·랜덤 삭제를 이용하는 간단한 기법입니다.

텍스트는 단어 하나가 문장의 감정이나 의도를 바꿀 수 있습니다. 예를 들어 부정어를 삭제하거나 상품명을 비슷한 단어로 바꾸면 라벨이 유지되지 않을 수 있습니다. 증강 문장을 일부 추출해 원문과 비교하고, 자동 변환을 사용할 때는 의미 보존 여부를 확인해야 합니다. 분류 라벨이 모호한 문장은 증강보다 라벨 품질을 먼저 점검하는 편이 낫습니다.

## 시계열 증강

시계열에서는 약한 잡음 추가, 크기 조정, 시간 축 변형, 구간 자르기 등을 사용할 수 있습니다. 센서 측정의 작은 잡음은 현실적인 변동일 수 있지만, 값을 섞거나 시간 순서를 바꾸면 실제 시스템에서 일어나지 않는 패턴이 만들어질 수 있습니다. 특히 미래를 예측하는 문제에서 예측 기준 시점 뒤의 구간을 사용해 과거 샘플을 증강하면 시간 누수입니다.

분류용 시계열에서도 한 시계열 안의 관측값이 독립 표본이라고 가정하면 안 됩니다. 같은 사람이나 장비의 원본과 변형 샘플이 Train과 Test로 나뉘지 않도록 개체 단위로 먼저 분할합니다.

## 표 형태 데이터 증강

표 데이터의 클래스 불균형을 다룰 때는 SMOTE(Synthetic Minority Over-sampling Technique, 합성 소수 클래스 오버샘플링)를 사용할 수 있습니다. SMOTE는 소수 클래스 샘플과 가까운 이웃 사이를 보간해 합성 샘플을 생성합니다. 단순 복제와 달리 새로운 점을 만들지만, 범주형 변수가 섞여 있거나 변수 간 제약이 복잡하면 실제로 존재하기 어려운 조합이 만들어질 수 있습니다.

```python
from imblearn.over_sampling import SMOTE
from imblearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

model = Pipeline([
    ("scale", StandardScaler()),
    ("smote", SMOTE(random_state=42)),
    ("classifier", LogisticRegression(max_iter=1000)),
])

model.fit(X_train, y_train)
valid_probability = model.predict_proba(X_valid)[:, 1]
```

연속형과 범주형 변수가 함께 있으면 기본 SMOTE가 범주 코드를 보간해 잘못된 중간값을 만들 수 있습니다. 이 경우 SMOTENC처럼 범주형 변수를 구분하는 방법을 검토하거나 class weight와 비교합니다. Mixup은 두 샘플을 비율로 섞고 라벨도 같은 비율로 섞는 방법입니다. 두 샘플 사이 조합이 현실적인 문제인지, 분류 손실이 soft label을 지원하는지도 확인해야 합니다.

## 증강과 평가 데이터

먼저 원본 데이터를 Train·Validation·Test로 분리하고, 학습 중에만 Train 샘플을 증강합니다. 원본을 변형한 샘플을 만든 다음 분할하면 거의 같은 내용이 학습과 평가 양쪽에 들어가 성능이 부풀려질 수 있습니다. 교차 검증에서는 각 학습 fold 안에서만 증강이 수행되도록 Pipeline을 구성합니다.

성능은 증강을 넣기 전과 같은 분할·지표로 비교합니다. 전체 정확도만 볼 게 아니라 클래스별 Precision·Recall, 실제 입력 분포와 생성 표본의 차이, 증강 강도에 따른 안정성도 확인합니다. 합성 샘플이 늘어도 검증 성능이 좋아지지 않거나 희귀 사례를 놓치면 증강 규칙을 다시 설계해야 합니다.

## 정리

증강은 데이터 수를 기계적으로 늘리는 방법이 아니라, 정답을 보존하는 현실적인 변동을 학습에 제공하는 과정입니다. 이미지·텍스트·시계열·표 데이터마다 유효한 변형이 다르고 잘못된 변형은 라벨을 훼손할 수 있습니다. 원본 데이터를 먼저 분할하고 Train 안에서만 증강한 뒤, 증강 전후 성능과 생성 데이터의 타당성을 비교합니다.

## Q&A

> [!question] 데이터 증강을 하면 실제 데이터가 늘어난 것과 같은가요?
>
> 아닙니다. 변형이나 합성으로 관측 행은 늘지만 독립적인 현실 정보가 새로 생기는 것은 아닙니다. 원본의 한계와 편향도 함께 복제될 수 있으므로 증강만으로 데이터 품질 문제가 해결되지는 않습니다.

> [!question] SMOTE를 적용하면 소수 클래스 성능이 항상 좋아지나요?
>
> 아닙니다. 생성된 점이 실제 분포와 맞지 않으면 분류 경계가 나빠질 수 있습니다. class weight나 원본 학습과 동일한 검증 조건으로 비교합니다.

> [!question] Validation 데이터도 증강해야 하나요?
>
> 일반적인 평가는 실제 운영 입력을 대표하는 원본 Validation을 사용합니다. 학습용 변형을 Validation에 섞으면 실제 환경의 성능을 해석하기 어려워집니다.
