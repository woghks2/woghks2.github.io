# 11. 시계열 피처

시계열 피처는 관측값의 크기뿐 아니라 시간 순서, 반복 주기, 변화 방향을 모델에 전달합니다. 다음 시점의 값을 예측한다면 예측 시점에 알 수 있는 달력 정보와 그때까지 관측된 과거 값만 사용할 수 있습니다. 먼저 한 행이 어떤 시계열을 뜻하는지(series_id), 예측 시각, 예측 지평(horizon)을 정합니다.

## 달력 피처

날짜·시간 열에서 요일, 월, 분기, 시간대 등을 만들면 달력에 따라 반복되는 패턴을 표현할 수 있습니다. 날짜 열은 문자열 상태에서 .dt 연산을 할 수 없으므로 to_datetime으로 변환합니다. 시간대가 다른 자료라면 기준 시간대를 맞춰야 같은 시각의 요일과 시간이 일관되게 계산됩니다.

~~~python
import pandas as pd
import numpy as np

df["timestamp"] = pd.to_datetime(df["timestamp"])
df["hour"] = df["timestamp"].dt.hour
df["dayofweek"] = df["timestamp"].dt.dayofweek
df["dayofmonth"] = df["timestamp"].dt.day
df["month"] = df["timestamp"].dt.month
df["quarter"] = df["timestamp"].dt.quarter
df["is_weekend"] = (df["dayofweek"] >= 5).astype("int8")
df["days_in_month"] = df["timestamp"].dt.days_in_month
~~~

요일 번호나 월 번호를 정수 하나로 넣으면, 숫자 간 거리를 사용하는 모델은 6과 0이 멀다고 판단할 수 있습니다. 요일처럼 처음과 끝이 이어지는 변수는 사인·코사인 쌍으로 바꾸면 원형 구조를 보존할 수 있습니다. 요일의 주기는 7입니다.

~~~python
period = 7
position = df["dayofweek"]
df["weekday_sin"] = np.sin(2 * np.pi * position / period)
df["weekday_cos"] = np.cos(2 * np.pi * position / period)
~~~

같은 방식으로 하루 중 시간은 24, 연중 날짜는 보통 365 또는 365.25를 주기로 삼을 수 있습니다. 윤년이나 주차 경계가 중요한 문제에서는 주기 정의를 데이터 목적에 맞춥니다. 공휴일이나 영업일 피처는 미래 날짜에도 달력에서 알 수 있으나, 미래에 확정되지 않은 일정 정보는 예측 시점에 이용 가능했는지 확인해야 합니다.

## 지연값

지연값(lag)은 과거 관측을 현재 시점의 설명 변수로 옮깁니다. shift(1)은 같은 시계열의 바로 앞 행을 뜻합니다. 그룹별 시계열은 그룹과 시간순 정렬을 먼저 적용해야 다른 계열이나 미래 값이 섞이지 않습니다.

~~~python
df = df.sort_values(["series_id", "timestamp"]).copy()
g = df.groupby("series_id")["value"]

df["lag_1"] = g.shift(1)
df["lag_7"] = g.shift(7)
df["lag_28"] = g.shift(28)
~~~

매일 한 행씩 빠짐없이 있을 때 lag_7은 7일 전 값입니다. 날짜가 불규칙하거나 관측 누락이 있으면 단순 shift(7)은 일주일 전을 보장하지 않습니다. 일 단위 데이터로 재구성하거나 날짜 인덱스에 과거 시점을 정렬하는 방법을 선택합니다. 관측되지 않은 날을 0으로 채우는 것도 실제 0과 기록 누락을 구분할 수 있을 때만 타당합니다.

## 이동 통계

이동 평균·표준편차·최댓값은 최근 구간의 수준과 변동성을 요약합니다. 현재 시점 값을 예측하면서 그 값을 통계량에 포함하면 누수가 될 수 있으므로 보통 한 행 밀어 과거 관측만 계산합니다.

~~~python
df["mean_7"] = g.transform(
    lambda s: s.shift(1).rolling(window=7, min_periods=3).mean()
)
df["std_7"] = g.transform(
    lambda s: s.shift(1).rolling(window=7, min_periods=3).std()
)
df["max_28"] = g.transform(
    lambda s: s.shift(1).rolling(window=28, min_periods=7).max()
)
~~~

min_periods는 통계량을 계산하는 데 필요한 최소 관측 수입니다. 창 전체가 채워지기 전에도 계산하도록 작게 잡을 수 있지만, 초기 구간 통계는 표본이 적어 불안정할 수 있습니다. 관측 간격이 일정하지 않다면 행 기준 rolling(7) 대신 날짜 인덱스의 rolling("7D")로 실제 시간 범위를 지정합니다.

## 차분과 변화율

차분(difference)은 현재 값에서 과거 값을 빼 수준보다 변화를 나타냅니다. 1차 차분은 직전 값과의 변화, 계절 차분은 한 주기 전 값과의 차이입니다.

~~~python
df["diff_1"] = g.diff(1)
df["diff_7"] = g.diff(7)
df["pct_change_1"] = g.pct_change(1)
~~~

일별 자료의 주기가 7이라면 diff(7)은 일주일 전과의 차이를 표현합니다. 변화율은 이전 값이 0에 가깝거나 음수일 때 해석이 불안정할 수 있으므로 분모가 0인 행과 극단값을 확인합니다. 차분 초기 구간에 생기는 결측은 필요한 과거가 없다는 뜻이므로, 데이터 분할 후 처리 기준을 정합니다.

## 푸리에 피처

푸리에 피처(Fourier features)는 사인·코사인 곡선을 조합해 긴 주기나 부드러운 계절 변화를 표현합니다. 주기가 길 때 모든 날짜를 범주형으로 만드는 대신 적은 수의 피처로 반복 패턴을 나타낼 수 있습니다. 차수 K를 늘리면 복잡한 모양을 표현하지만 과적합 가능성도 커집니다.

~~~python
# t는 일정한 간격으로 증가하는 시간 인덱스, P는 주기 길이
P = 365.25
t = (df["timestamp"] - df["timestamp"].min()).dt.days

for k in range(1, 4):
    df[f"year_sin_{k}"] = np.sin(2 * np.pi * k * t / P)
    df[f"year_cos_{k}"] = np.cos(2 * np.pi * k * t / P)
~~~

푸리에 피처는 시간이 흐를수록 부드럽게 바뀌는 계절성을 나타냅니다. 윤년이나 특정 공휴일 효과를 직접 표현하지는 않으므로 달력 피처와 함께 쓰거나 시간 기준 검증으로 비교합니다. 주기 P와 차수 K는 검증 구간 성능을 바탕으로 선택합니다.

## 시간 검증

시계열 예측은 무작위 분할보다 과거로 학습하고 미래로 평가하는 방식이 적절합니다. 예측 지평이 7일이라면 실제 운영처럼 검증 기준일에서 이용 가능한 과거와 7일 뒤의 정답을 대응시킵니다. 기준 시점을 순차적으로 옮기는 롤링 오리진 검증(rolling-origin validation)은 특정 기간에만 잘 맞는지 확인하는 방법입니다.

결측 대체값, 스케일러, 인코더처럼 데이터에서 값을 학습하는 전처리는 각 학습 구간에만 fit하고 검증·테스트에는 transform만 적용합니다. lag와 rolling 계산도 운영 시점에 이용 가능한 이력만 전달해야 합니다. 검증 구간 실제값을 다음 시점 피처에 넣는 것이 허용되는지는 순차 예측인지, 여러 시점을 한 번에 예측하는지에 따라 달라집니다.

## 정리

달력 피처는 반복되는 시간 효과를, lag와 이동 통계는 과거 수준과 변동을, 차분은 변화량을, 푸리에 피처는 부드러운 장주기를 표현합니다. 시계열별로 정렬하고 예측 시점에 알 수 있는 값만 사용합니다. shift는 이전 행을 뜻하므로 실제 날짜 간격과 예측 지평을 점검하고, 평가는 과거에서 미래 방향으로 진행합니다.

## Q&A

> [!question] shift(7)이면 항상 7일 전 값인가요?
>
> 아닙니다. 매일 한 행씩 빠짐없이 기록된 자료에서만 7일 전을 뜻합니다. 불규칙한 자료에서는 7개 관측 전일 수 있으므로 날짜 기준 재구성이나 시간 인덱스 계산을 사용합니다.

> [!question] 요일을 정수와 사인·코사인 중 어떤 방식으로 넣나요?
>
> 선형 모델처럼 숫자 간격을 사용하는 경우 사인·코사인으로 순환성을 표현할 수 있습니다. 트리 모델은 정수 피처를 다르게 처리하므로 표현 방식을 시간 기준 검증으로 비교합니다.

> [!question] 검증 구간의 첫 lag에 학습 구간 마지막 값을 써도 되나요?
>
> 예측 시점에 그 값이 실제로 관측되어 있다면 사용할 수 있습니다. 아직 관측되지 않은 검증 정답을 다음 시점 피처에 넣으면 누수입니다. 순차 예측인지 여러 시점을 한꺼번에 예측하는지에 맞춰 생성 절차를 정합니다.
