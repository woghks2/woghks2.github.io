# 1. SMOTE (Synthetic Minority Over-sampling Technique)

사기 탐지(Fraud), 이탈 예측(Churn), 전환율(Conversion) 예측 등 정형 데이터 문제의 90% 이상은 소수 클래스 비율이 희박한 불균형 데이터(Imbalanced Data)입니다.

불균형 데이터를 다루는 접근법은 크게 둘로 나뉩니다.
1. **데이터 레벨 (Data-level)**: 피처 공간에 가상 샘플을 만들어 비율을 맞춘다 $\rightarrow$ **SMOTE 및 오버샘플링 계열**
2. **알고리즘 레벨 (Algorithm-level)**: 데이터는 보존하고 손실(Loss) 계산 가중치를 재조정한다 $\rightarrow$ **비용 민감 학습 (Class Weight)**

두 기법의 세부 메커니즘과 모델별 구현 차이, 그리고 실무에서의 선택 기준을 깊이 있게 분석합니다.

---

## 1. SMOTE와 파생 기법들: 왜 여전히 기본 SMOTE가 기준점인가?

단순히 소수 데이터를 복제하는 **Random Over-sampling**은 동일한 점에 가중치만 더해져 결정 트리가 해당 데이터 포인트 하나만을 위한 전용 리프 노드(독방)를 파게 만들어 심각한 과적합을 유발합니다. 

이를 해결하기 위해 등장한 것이 선형 보간 기반의 **SMOTE**입니다. 

### SMOTE 작동 4단계

1. 기준점 선택:전체 소수 클래스 데이터 중 하나($x_i$)를 무작위로 고릅니다.
2. 이웃 탐색 (K-NN):그 기준점($x_i$)과 유클리디안 거리가 가장 가까운 소수 클래스 데이터 $k$개를 찾습니다. (보통 $k=5$)
3. 파트너 점 선택:찾아낸 $k$개의 이웃 중 하나($x_{neighbor}$)를 무작위로 고릅니다.
4. 내분점 생성 (합성):두 점 사이의 거리 벡터에 0과 1 사이의 난수($\lambda \in [0, 1]$)를 곱해 새로운 가짜 샘플($x_{new}$)을 만듭니다.

기본적으로 KNN과 벡터공간 내 내분점을 사용하여 새로운 가짜 샘플을 생성합니다.

### 1-1. SMOTE 계열 기법별 메커니즘 비교

| 기법 | 핵심 아이디어 및 생성 방식 | 장점 | 치명적 한계 |
| :--- | :--- | :--- | :--- |
| **기본 SMOTE** | 소수 클래스 점 $x_i$와 K-NN 이웃 $x_{zi}$ 사이의 선상에 무작위 합성:<br>$x_{new} = x_i + \lambda(x_{zi} - x_i)$ | 구현이 단순하고 전체적인 소수 클래스 밀도를 균등하게 채움 | 다수 클래스 깊숙이 들어간 이상치(Outlier) 주변에도 가짜 점을 찍어 **노이즈 증폭** |
| **Borderline-SMOTE** | K-NN 중 다수 클래스가 절반 이상 섞여 있는 **결정 경계(DANGER 구역)**의 소수 샘플만 골라 합성 | 분류기가 헷갈려하는 결정 경계면을 집중적으로 보강 | 경계면에 존재하는 실제 노이즈나 라벨링 오류까지 집중 증폭할 위험 |
| **ADASYN** | 주변에 다수 클래스가 많아 **분류 난이도가 높은 소수 샘플일수록 더 많은 샘플을 가중 합성** | 분류하기 어려운 영역의 밀도를 적응적(Adaptive)으로 복원 | 극단적 이상치(Outlier) 주변에 가짜 데이터가 대량 생성되어 경계 왜곡 극대화 |
| **SMOTE-NC** | 수치형은 유클리디안 거리 보간, 범주형은 이웃들의 **최빈값(Mode)**으로 채택 | 범주형/정수형 피처가 섞인 테이블 데이터 처리 가능 | 고차원 원-핫 인코딩 환경에서 연산 복잡도와 거리 척도 왜곡 급증 |

### 1-2. 그럼에도 실무에서 기본 SMOTE를 가장 먼저 쓰는 이유
* **파라미터 민감도**: Borderline-SMOTE나 ADASYN은 '어디까지를 위험/어려운 샘플로 볼 것인가'에 대한 하이퍼파라미터($k$, threshold)가 추가되어 튜닝 비용이 큽니다.
* **노이즈 폭탄 방지**: 현실의 정형 데이터는 라벨링 노이즈가 많습니다. ADASYN처럼 분류하기 어려운 샘플에 가중치를 주면, **잘못 라벨링된 노이즈 데이터 주변에 가짜 데이터를 수백 개 찍어내 모델을 망치는 역효과**가 발생하기 쉽습니다.
* 따라서 오버샘플링을 시도할 때는 **기본 SMOTE를 기준선(Baseline)**으로 삼고, 경계선 모호성이 확실할 때만 Borderline 기법을 제한적으로 검토합니다.

## 2. 모델별 Class Weight 메커니즘과 수식 차이

Class Weight는 데이터셋 행(Row)을 단 하나도 조작하지 않습니다. 대신 소수 클래스를 틀렸을 때 손실 함수에 가하는 Penalty를 높여 모델이 소수 클래스에 더 집중하도록 만듭니다.

하지만 어떤 모델을 쓰느냐에 따라 가중치를 반영하는 수학적 메커니즘이 완전히 다릅니다.

### 2-1. Scikit-learn (Logistic Regression, Random Forest)
Scikit-learn의 표준 `class_weight='balanced'` 옵션은 전체 데이터셋의 역빈도(Inverse Frequency)를 이용해 가중치를 자동 계산합니다.

$$w_k = \frac{N}{C \times n_k}$$

* $N$: 전체 샘플 수, $C$: 클래스 개수(이진 분류는 2), $n_k$: 클래스 $k$의 샘플 수
* **동작 방식**: 
  * **로지스틱 회귀**: 로그 손실(Log-Loss)의 각 샘플 오차 항에 $w_k$가 단순 곱해집니다.
  * **랜덤 포레스트**: 노드 분할 시 계산하는 불순도(Gini, Entropy) 계산식에서 각 샘플의 빈도를 셀 때 $w_k$ 가중치로 카운트합니다.

---

### 2-2. XGBoost: `scale_pos_weight`
XGBoost는 음성 클래스($y=0$) 대비 양성 클래스($y=1$, 소수 클래스)의 상대 비율 하나만을 파라미터로 받습니다.

$$\text{scale\_pos\_weight} = \frac{\sum (y_i = 0)}{\sum (y_i = 1)} = \frac{\text{음성 샘플 수}}{\text{양성 샘플 수}}$$

#### 목적 함수와 Gradient/Hessian 내부 작동
XGBoost의 손실 함수에서 양성 클래스 항에만 $\alpha = \text{scale\_pos\_weight}$가 곱해집니다.

$$\mathcal{L} = - \sum_{i \in \text{pos}} \alpha \left[ y_i \log(\hat{y}_i) \right] - \sum_{i \in \text{neg}} (1 - y_i) \log(1 - \hat{y}_i)$$

이로 인해 테일러 전개 시의 1차 미분(Gradient $g_i$)과 2차 미분(Hessian $h_i$)이 다음과 같이 변환됩니다.

| 클래스 | 기본 Gradient ($g_i$) | `scale_pos_weight` 적용 후 ($g_i^*$) | 기본 Hessian ($h_i$) | `scale_pos_weight` 적용 후 ($h_i^*$) |
| :--- | :--- | :--- | :--- | :--- |
| **음성 ($y=0$)** | $p_i$ | $p_i$ | $p_i(1 - p_i)$ | $p_i(1 - p_i)$ |
| **양성 ($y=1$)** | $p_i - 1$ | $\mathbf{\alpha (p_i - 1)}$ | $p_i(1 - p_i)$ | $\mathbf{\alpha \cdot p_i(1 - p_i)}$ |

* **노드 분할(Gain)에 미치는 영향**:  
  양성 클래스의 $G_j = \sum g_i$가 $\alpha$배로 커집니다. XGBoost의 분할 점수는 $G^2$에 비례하므로, **양성 클래스를 분리해내는 후보 분기점의 분할 이득(Gain)이 최대 $\alpha^2$ 수준으로 폭증**하여 트리가 양성 샘플을 분리하는 쪽으로 강하게 유도됩니다.

#### 1. 양성 샘플을 분리 유도

* **공격적인 분기 채택**: 모델 입장에서 소수 클래스($y=1$)를 놓치는 오차(FN)는 엄청난 손실 폭탄입니다. 따라서 트리는 소수 클래스가 섞여 있을 가능성이 조금이라도 보이면, 다수 클래스($y=0$)가 일부 섞여 들어오더라도 **일단 양성 리프 노드로 묶어내는 분할**을 적극 채택합니다.
* **지표 트레이드오프**:
  * **Recall(재현율) 상승**: 소수 클래스를 놓치지 않고 최대한 공격적으로 긁어모읍니다.
  * **Precision(정밀도) 하락**: 억울한 다수 클래스까지 양성으로 대거 지목되어 오탐(False Positive)이 증가합니다.

#### 2. 모델 평가 시 고려해야 할 점

가중치 부여로 인해 모델의 예측 확률 분포가 왜곡되므로, 기본 세팅 그대로 평가하면 심각한 착시가 발생합니다.

* **기본 임계값(`Threshold = 0.5`) 사용 금지 (확률 인플레이션)**:
  * 양성 오차에 큰 벌점이 걸려 리프 노드의 최적 출력값($w^*$)이 양수 방향으로 강하게 치우칩니다.
  * 결과적으로 `predict_proba()`의 출력값이 실제 빈도보다 전반적으로 뻥튀기(예: 실제 발생 확률 20%인 데이터가 0.7~0.8로 출력)됩니다.
  * 따라서 0.5를 기준으로 자르면 모델이 거의 모든 데이터를 양성으로 예측해버리므로, **반드시 Validation Set에서 비즈니스 목적(F1-score 최적화, 정밀도/재현율 타협점)에 맞는 별도의 최적 Threshold를 탐색**해야 합니다.
* **점수의 본질은 절대 확률이 아닌 '우선순위 랭킹'**:
  * 확률의 절대적 수치는 왜곡되지만, 샘플들 간의 상대적인 순위(Ranking)는 유지됩니다.
  * 따라서 모델 출력값을 "실제 발생 확률(%)"로 직접 해석하기보다는, CRM 타겟팅이나 이상 거래 탐지를 위한 우선순위 랭킹 점수(Ranking Score)로 다루고 PR-AUC나 Top-K Lift로 평가하는 것이 적합합니다.

### 2-3. LightGBM: `is_unbalance` vs `scale_pos_weight`
LightGBM은 두 가지 옵션을 모두 제공합니다.

1. **`is_unbalance=True` (간이 자동 설정)**:
   * 내부적으로 $\frac{\text{음성 샘플 수}}{\text{양성 샘플 수}}$ 비율을 자동 계산하여 양성 클래스의 Gradient에 가중치를 부여합니다.
2. **`scale_pos_weight` (정밀 수동 제어)**:
   * XGBoost와 동일하게 작동하며, 가중치 크기를 직접 숫자로 조율합니다.

> 트리 부스팅 모델 주의점 (확률 왜곡 현상):  
> `scale_pos_weight`를 크게 주면 모델의 원시 출력값(Raw Output)이 양성 쪽으로 강하게 밀려나기 때문에, `predict_proba()`가 출력하는 예측 확률값이 실제 현실의 발생 빈도보다 높게 왜곡됩니다.  
> 따라서 모델 출력을 절대적인 확률값으로 써야 한다면 반드시 Platt Scaling이나 Isotonic Regression 같은 보정(Calibration)을 거쳐야 합니다.

## 3. 심층 비교: SMOTE vs Class Weight

| 비교 항목 | SMOTE (데이터 레벨) | Class Weight (알고리즘 레벨) |
| :--- | :--- | :--- |
| **동작 계층** | `Data Handling` (전처리 파이프라인) | `Training & Optimization` (목적 함수) |
| **데이터 변경** | 합성 샘플 추가로 **행 수($N$) 증가** | 원본 데이터 수 및 피처값 **100% 보존** |
| **정수/범주형 피처** | 두 점 사이 실수 보간으로 **비현실적 데이터 생성 위험** | 실제 관측값만 사용하므로 무결성 유지 |
| **메모리 및 속도** | K-NN 연산 비용 발생 + 행 증가로 학습 지연 | 추가 연산 오버헤드 거의 없음 ($O(1)$) |
| **누수(Leakage) 위험** | 매우 높음 (반드시 CV 내부에서 분리 적용해야 함) | 없음 |
| **해석력 (Explainability)** | 합성된 가짜 점으로 인해 SHAP 경계선 왜곡 가능 | 실제 데이터 기준 Feature Importance 산출 |

---

## 요약

1. **SMOTE**는 K-NN 기반 선형 보간으로 결정 경계를 넓혀주지만, 비현실적인 정수/범주형 데이터 생성과 노이즈 증폭 위험이 상존합니다.
2. **Class Weight**는 데이터의 무결성을 지키면서 손실 함수와 Gradient/Hessian 스케일을 조정해 모델의 집중도를 바꾸는 가장 깔끔한 엔지니어링 접근법입니다.
3. 실무에서는 **`scale_pos_weight` 기반의 가중치 조절을 1차 베이스라인**으로 설정하고, 연속형 변수 위주이면서 소수 클래스 수가 극도로 부족할 때 보조 수단으로 SMOTE를 도입하는 것이 권장됩니다.

본 포스팅은 개인적인 학습 내용을 바탕으로 작성되었으며, 가독성과 내용 보완을 위해 생성형 AI의 도움을 받아 재작성되었습니다.
