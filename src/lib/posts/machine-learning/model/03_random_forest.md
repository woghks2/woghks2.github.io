# 03. 랜덤 포레스트 (Random Forest)

결정 트리는 구조가 단순하고 결과를 규칙으로 설명하기 쉽습니다. 다만 데이터가 조금만 달라져도 분할 기준이 크게 바뀔 수 있고, 깊게 자라면 학습 데이터의 잡음까지 따라가 과적합되기 쉽습니다. 랜덤 포레스트는 여러 결정 트리의 예측을 모아 이런 불안정성을 줄이는 앙상블 모델입니다.

앙상블은 여러 모델의 예측을 결합해 최종 결과를 만드는 방법입니다. 결합하는 방식에 따라 배깅과 부스팅 등으로 나뉘는데, 랜덤 포레스트는 배깅을 기반으로 합니다. 부스팅은 다음 글에서 살펴보겠습니다.

## 배깅

배깅(Bagging)은 Bootstrap Aggregating을 줄인 말입니다. 원본 데이터에서 복원 추출로 여러 학습 데이터를 만들고, 각 데이터로 별도의 모델을 학습한 뒤 예측을 결합합니다. 분류에서는 보통 다수결을 사용하고, 회귀에서는 예측값의 평균을 사용합니다.

복원 추출에서는 같은 샘플이 한 학습 데이터에 여러 번 포함될 수 있고, 뽑히지 않는 샘플도 생깁니다. 특정 모델을 학습할 때 선택되지 않은 샘플을 OOB(Out-of-Bag) 샘플이라고 합니다. 학습에서 제외된 샘플을 해당 모델의 예측에 활용할 수 있어, 별도 검증 데이터와는 다른 참고 성능을 계산할 수 있습니다.

## 랜덤 포레스트의 동작

랜덤 포레스트는 결정 트리에 배깅을 적용하고, 각 노드의 분할 후보에서도 일부 특성만 무작위로 선택합니다. 데이터 샘플과 특성 선택에 모두 무작위성이 들어가기 때문에 트리마다 다른 분할을 학습하게 됩니다.

이 차이가 중요한 이유는 트리 개수만 늘린다고 예측이 항상 안정되는 것은 아니기 때문입니다. 트리들이 거의 같은 데이터와 같은 특성에 의존하면 비슷한 오답을 반복할 수 있습니다. 트리들이 서로 다른 패턴을 학습하도록 만들수록 예측을 결합했을 때 개별 트리의 오차가 상쇄될 여지가 커집니다.

랜덤 포레스트는 보통 개별 트리를 충분히 성장시켜 편향을 낮추고, 여러 트리의 예측을 결합해 분산을 줄이는 방향으로 사용합니다. 다만 모든 트리를 무조건 끝까지 키워야 하는 것은 아닙니다. 데이터와 평가 기준에 따라 `max_depth`, `min_samples_leaf` 같은 설정을 조정하고 검증 성능으로 확인해야 합니다.

랜덤 포레스트는 특성 간 비선형 관계와 상호작용을 별도의 수식으로 지정하지 않아도 학습할 수 있고, 특성 스케일 변화에도 대체로 민감하지 않습니다.

반면 단일 트리처럼 예측 경로를 바로 읽기 어렵고, 트리 수와 데이터가 커지면 모델 크기와 예측 비용도 증가합니다. `feature_importances_`는 분할에 따른 불순도 감소량을 기반으로 계산되므로, 값이 크다고 해서 해당 특성이 결과의 원인이라고 해석하면 안 됩니다. 특성 간 상관관계나 고유값 개수에 따라 중요도가 달라질 수 있어 필요하면 permutation importance 등 다른 방법과 함께 확인합니다.

## 정리

랜덤 포레스트는 여러 결정 트리를 서로 다른 데이터와 특성으로 학습한 뒤, 그 예측을 결합하는 모델입니다. 배깅과 특성 무작위 선택으로 트리 간 유사성을 낮추고, 개별 트리의 불안정성이 최종 예측에 미치는 영향을 줄입니다.

따라서 핵심은 단순히 트리를 많이 만드는 데 있지 않습니다. 트리들이 서로 다른 오차를 내도록 학습시키고, 그 결과를 평균이나 다수결로 모으는 데 있습니다. 다음 글에서는 순차적으로 이전 모델의 오차를 보완하는 부스팅과 XGBoost를 살펴보겠습니다.

## Q&A

> [!question] 랜덤 포레스트는 어떤 앙상블 기법을 사용하나요?
>
> 복원추출로 여러 학습 데이터를 만들고 학습을 진행한 뒤 보팅을 진행하는 배깅 방식을 사용합니다.
> -> 서로 다른 데이터 샘플과 feature 집합으로 여러 트리를 만든 뒤 결과를 종합하기 때문에 개별 트리의 과적합이 평균 과정에서 완화된다.

> [!question] OOB 샘플은 검증 데이터와 같은가요?
>
> 아닙니다. 각 트리의 bootstrap 표본에서 빠진 학습 샘플을 해당 트리의 평가에 활용하는 방식입니다. 모델이나 기준을 반복해서 선택하는 최종 검증을 완전히 대체하지는 않으므로, 독립된 검증·테스트 데이터도 확인해야 합니다.

>[!question] 부트스트랩 대신 K-Fold Cross Validation처럼 데이터를 나누어 진행하면 성능이 더 좋아지나요?
>
> 결정 트리는 데이터 양에 민감하기 때문에 샘플 수가 너무 적어지면 트리가 데이터의 전반적인 규칙을 제대로 파악하지 못해 편향(Bias)이 급격히 증가하는 언더피팅이 발생할 수 있습니다. -> CV처럼 쪼개는 방식은 Stacking(여러 모델이 내놓은 예측값들을 새로운 입력 데이터(Feature)로 삼아서, 또 다른 모델이 최종 예측을 학습하게 만드는 앙상블 기법)에서 사용!

본 포스팅은 개인적인 학습 내용을 바탕으로 작성되었으며, 가독성과 내용 보완을 위해 생성형 AI의 도움을 받아 재작성되었습니다.
