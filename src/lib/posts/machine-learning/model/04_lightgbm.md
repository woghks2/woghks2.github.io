# 04. LightGBM (Lightweight Gradient Boosting Machine)

앞서 살펴본 **XGBoost**는 2차 테일러 전개와 정규화(규제)를 통해 모델의 예측력과 안정성을 극대화했습니다. 하지만 여전히 대용량 데이터(수백만 행, 수백 개 특성) 앞에서는 모든 샘플과 특성을 전수 조사하느라 계산량과 메모리 소모가 크다는 한계가 있었습니다.

LightGBM은 이 연산 병목을 해결하기 위해 등장한 알고리즘입니다. "정확도는 거의 그대로 유지하면서, 연산량을 10배 이상 줄인다"는 목표 아래 개발되었으며, 핵심 아이디어는 크게 4가지로 요약됩니다.

---

## 1. 히스토그램 기반 분할 (Histogram-based Splitting)

Decision Tree 내용에서도 나왔지만 전통적인 결정 트리나 초기 부스팅 모델은 모든 데이터 포인트를 정렬한 뒤 가능한 모든 분할점을 일일이 검사했기 때문에 연산량이 많아지는 단점이 있습니다.

LightGBM은 연속형 특성값을 256개 정도의 구간(Bin)으로 이산화(Discretization)합니다.

- 데이터를 정렬할 필요 없이, 각 구간별로 데이터 통계(Gradient의 합, Hessian의 합)를 담은 **히스토그램**을 만듭니다.
- 분할점을 찾을 때 데이터 전체 수($N$)를 순회하는 대신, \*\*Bin의 개수($K \approx 255$)\*\*만 순회하면 되므로 분할 탐색 시간복잡도가 $O(N \times \text{Feature})$에서 $O(K \times \text{Feature})$로 대폭 감소합니다.
- 메모리 사용량도 실수형(Float 32bit/64bit) 대신 8bit 정수로 압축되어 획기적으로 줄어듭니다.

## 2. GOSS (Gradient-based One-Side Sampling)

데이터 행을 줄이기 위한 방법으로 샘플의 중요도에 따라서 샘플링을 하는 기법입니다. 오차(Gradient)가 큰 샘플은 아직 학습이 덜 된 중요한 데이터지만, Gradient가 작은 샘플은 이미 정답에 가까워 배울 게 적다고 판단합니다.

학습을 순차적으로 진행하기 때문에 이전 모델에서 Gradient를 바탕으로 손실이 큰 상위 데이터와 손실이 작은 하위 데이터를 나누어 사용합니다. Gradient가 작은 샘플을 무작정 버리면 데이터의 원래 분포가 왜곡되기 때문에 GOSS는 한쪽(One-side)만 샘플링하는 기법을 씁니다.

1. **상위 추출**: Gradient 절댓값이 큰 **상위 $a \times 100%$ 데이터는 100% 보존**합니다.
2. **하위 샘플링**: Gradient가 작은 나머지 데이터군에서 **$b \times 100%$만 무작위(Random)로 추출**합니다.
3. **분포 보정 (가중치 증폭)**: 덜 뽑힌 작은 Gradient 샘플들에 보정 가중치 $\frac{1-a}{b}$를 곱해 원래 데이터 크기의 영향력을 복원합니다.

$$\tilde{V}*j(d) = \frac{1}{n}\left( \frac{\left(\sum*{x\_i \in A\_l} g\_i + \frac{1-a}{b}\sum\_{x\_i \in B\_l} g\_i\right)^2}{n\_l^j(d)} + \frac{\left(\sum\_{x\_i \in A\_r} g\_i + \frac{1-a}{b}\sum\_{x\_i \in B\_r} g\_i\right)^2}{n\_r^j(d)} \right)$$

수학적으로 데이터 크기 $n$이 충분히 크다면, 이렇게 계산한 분산 이득(Variance Gain)과 전체 데이터를 다 썼을 때의 오차는 0으로 수렴합니다. 즉, **데이터의 10\~20%만 보면서도 전체 데이터를 학습한 것과 거의 같은 효과**를 냅니다.

## 3. EFB (Exclusive Feature Bundling)

Column을 줄이기 위한 방법으로 Column의 범주를 합치는 기법입니다. 고차원 대규모 데이터는 Sparse한 경우가 많기 때문에 LightGBM은 동시에 0이 아닌 값을 가질 일이 거의 없는 특성들(상호 배타적 특성, Mutually Exclusive Features)을 하나로 묶어(Bundle) 새로운 하나의 특성으로 합칩니다.

### One-Hot Encoding

된 변수들은 동시에 1이 될 수 없습니다. 이를 특성 여러 개로 둘 필요 없이 하나의 범주로 합치는 식입니다.

1. 데이터 1	[1, 0, 0]	-> 1
2. 데이터 2	[0, 1, 0]	-> 2
3. 데이터 3	[0, 0, 1]	-> 3

### **오프셋(Offset)을 통한 충돌 방지**:

- 특성 A의 범위가 $[0, 10]$이고 특성 B의 범위가 $[0, 20]$이라면,
- 특성 B의 값에 10(오프셋)을 더해 범위를 $[10, 30]$으로 바꾼 뒤 하나의 칼럼으로 합칩니다.
- 이렇게 하면 하나의 값만 보고도 원래 특성 A의 값인지 B의 값인지 완벽히 복원할 수 있습니다.

완벽하게 배타적이지 않더라도 사소한 충돌(Conflict)은 약간 허용하며 그리디(Greedy)하게 묶어버립니다. 이를 통해 모델이 봐야 할 **특성의 절대적인 개수(열 수)를 대폭 줄여 연산 속도를 극대화**합니다.

## 4. Leaf-wise

기존 트리 모델(XGBoost 기본형 포함)은 트리의 균형을 맞추며 층별로 키워나가는 **Level-wise(수평 성장)** 방식을 주로 썼습니다.

반면 LightGBM은 **Leaf-wise(수직 성장)** 방식을 사용합니다.

- **동작 원리**: 트리의 균형(Balance)을 신경 쓰지 않고, 현재 존재하는 리프 노드들 중 **손실(Loss)을 가장 많이 줄여줄 수 있는 단 하나의 리프를 골라 그 부분만 집중적으로 분할**합니다.
- **장점**: 같은 분할 횟수 대비 Level-wise보다 훨씬 빠르게 오차를 줄여 성능이 더 잘 나옵니다.
- **단점**: 특정 가지(Branch)만 비대칭적으로 깊어질 수 있어, **데이터가 작거나 규제가 없으면 과적합(Overfitting)에 매우 취약**합니다.

---

## 5. 하이퍼파라미터

Leaf-wise 구조를 갖기 때문에 XGBoost와는 튜닝 접근법이 약간 다릅니다.

| 파라미터                                    | 연결된 메커니즘         | 역할 및 튜닝 직관                                                                    |
| :-------------------------------------- | :--------------- | :---------------------------------------------------------------------------- |
| `num_leaves`                            | Leaf-wise 구조     | **가장 핵심적인 파라미터**. 트리 복잡도를 결정하며, 일반적으로 $2^{\text{max\_depth}}$보다 작게 설정해 과적합 방지 |
| `min_data_in_leaf`                      | Leaf-wise 과적합 제어 | 리프 노드가 가져야 할 최소 샘플 수. Leaf-wise 특유의 뾰족한 과적합 가지를 막는 핵심 안전장치                    |
| `max_depth`                             | 수직 성장 제한         | 트리의 최대 깊이를 강제로 제한해 과적합 억제                                                     |
| `learning_rate`                         | 부스팅 축소율          | 트리의 반영 비율. 작게 두고 `n_estimators`를 넉넉히 준 뒤 Early Stopping 활용                    |
| `feature_fraction` / `bagging_fraction` | 무작위 샘플링          | 특성과 데이터 샘플의 일부만 사용하여 과적합 억제 및 속도 향상                                           |

---

## 정리

1. **GOSS와 EFB**: GOSS로 오차가 작은 샘플(행)을 덜어내고, EFB로 희소한 특성(열)들을 묶어내어 **데이터 테이블 자체의 크기를 압축**합니다.
2. EFB를 통해 완벽하게 특성의 절대적인 개수 줄여 연산 속도를 극대화합니다.
3. **히스토그램 기반 탐색**: 데이터를 정렬하지 않고 256개 안팎의 Bin으로 다루어 **메모리 절약과 초고속 분할**을 달성했습니다.
4. **Leaf-wise 성장**: 손실 감소가 가장 큰 리프만 비대칭적으로 파고들어 **적은 트리 크기로도 뛰어난 예측력**을 내지만, 그만큼 `num_leaves`와 `min_data_in_leaf`로 과적합을 신경 써서 제어해야 합니다.

### Q&A

> [!question] LightGBM은 작은 데이터셋에서 쓰면 왜 안 좋다고 할까요?
>
> Leaf-wise 방식은 손실 감소가 큰 특정 패턴을 매우 공격적으로 깊게 파고들기 때문이다. 데이터 양이 적으면 데이터 전반의 보편적 규칙 대신 소수 샘플의 노이즈까지 하나의 깊은 리프로 외워버려 과적합이 쉽게 발생한다. 데이터가 1만 건 미만으로 작다면 보수적인 트리나 정규화가 강한 모델이 더 낫다.

> [!question] XGBoost와 LightGBM 중 실무에서는 무엇을 먼저 선택해야 할까요?
>
> 데이터 규모가 크거나 특성이 많아 빠른 실험 사이클이 중요할 때는 압도적인 학습 속도와 가벼운 메모리를 자랑하는 **LightGBM**이 유리하다. 반면 데이터셋이 비교적 작고 정밀한 튜닝과 보수적인 안정성이 필요할 때는 **XGBoost**가 든든한 기준점이 된다. (최근 XGBoost도 히스토그램 분할(`tree_method='hist'`)을 도입해 둘의 속도 격차가 많이 줄어들었다.)
